## Automatic publication SEO and author management

Publishing now automatically produces a work-and-author title, an excerpt-based description (using the optional introduction when supplied), canonical URL, social image metadata, Article and breadcrumb structured data, author links and a sitemap entry. Public modification dates change on publication, not autosave; publishing the same revision again keeps the date stable. Editor pages expose ProfilePage data based on the existing biography and portrait. The homepage links the editors and public literary sections, and Eseji describes literary criticism without restoring the retired category. Regional relevance comes from visible editorial content, not hidden keywords or invented local pages.

Editors can delete an author in Autori only when no revision references that author. Connected drafts, live/unpublished texts and historical versions return a clear conflict message. Deletion requires an editor session, origin validation and UI confirmation. Author writes and deletion coordinate row locks to protect concurrent saves. API checks and mobile browser checks cover successful deletion and refusals.

The administrator installed the www virtual host with `deploy/configure-www.sh`. Both HTTP and HTTPS www requests now return a 301 to the apex while preserving the path and query; TLS verification succeeds. The script waits for graceful reload completion before checking the redirect and preserves the previous Nginx configuration as a backup.
